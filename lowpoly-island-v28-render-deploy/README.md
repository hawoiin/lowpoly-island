# 探索の島 — マルチプレイ版 (v48)

Three.js の単一HTMLゲームを、Node.js(WebSocket)でマルチプレイ化したものです。

## 起動

```
start.bat          # Windows: ダブルクリックで起動(初回は自動で npm install、ブラウザも開く)

# 手動の場合
npm install
npm start          # http://localhost:4010
```

- 友達と遊ぶ場合は、サーバーのPCのIPアドレス(例 `http://192.168.x.x:4010`)を共有します。インターネット越しなら、ポート転送かトンネル(cloudflared / ngrok など)を使ってください。
- `PORT`(既定4010)、`MAX_PLAYERS`(既定16)、`SAVE_FILE`(既定 `world.json`)を環境変数で変えられます。
- `PICKUP_OTHERS=1` にすると、他人の建築物も回収できます(既定は持ち主だけ)。
- サーバーに繋がらない場合や `file://` で直接開いた場合は、ブラウザ内で同じ仕組みが動く**ソロモード**になります。
- `npm test` で入力検証の単体テストと WebSocket プロトコルのテストが走ります(事前に `npm install` が必要です)。

## 仕組み

| 役割 | 内容 |
|---|---|
| サーバー(`shared.js` の `WorldSim`) | 敵のAI・HP・再出現、採集物の取得(先着判定)と再生、建築物、宝箱、ワールド保存 |
| クライアント(`index.html`) | 地形・木・岩・遺跡・洞窟をシードから生成(全員同じ島)、入力、描画、補間 |
| 起動と通信(`boot.js`) | サーバーへの接続、繋がらなければソロ、切断時の自動再接続 |
| 同期 | プレイヤー状態は約15Hzで送信、サーバーは10Hzで敵と全員の位置を配信 |

- 建築物と開封済みの宝箱は `world.json` に保存され、サーバーを再起動しても残ります。遺跡・宝箱の座標はシードから共有関数で生成し、サーバーも同じ座標を持ちます。
- セーブ読み込み時は建築物のID・種類・座標・回転と宝箱番号を検証し、不正なレコードを復元しません。宝箱番号は現行ワールドの配置数(陸上3個・沈没船・灯台・野営地3か所・海底洞窟、最大9個)と一致させています。配置方式が旧版のセーブでは、宝箱の開封状態だけをリセットし、別の場所の宝箱に誤適用しません。
- 所持品・図鑑・剣の強化は各自のブラウザ(localStorage)に保存されます。
- 建築物の持ち主は、ブラウザごとのキー(localStorage)から作った識別子で判定します。再接続しても同じ人として扱われ、サーバーにはハッシュだけが残ります。
- 設置できる場所の判定(海・洞窟の周り・他の建物との重なり・地面との高さ)は `shared.js` の `checkPlacement` で、サーバーとクライアントが同じものを使います。置けない場所ではゴーストが赤くなり、理由が表示されます。`R`キー(Shiftで逆回し)か「回転」ボタンで向きを変えられます。
- **建築スナップ:** 柵と門は既存の柵・門の端に近づけると端点どうしが合う位置へ自動吸着し、向きを変えれば直角のコーナーにも接続できます。柵の囲いを閉じるときは、連続設置を中断していても、既存柵の開いた端どうしが1本で届く距離にあり、カーソルが隙間の近くなら最後の柵の長さと角度を自動調整します。床は既存の床の4辺に吸着し、高さと向きを引き継いで縁を揃えます。吸着位置が他の建築物と重なる場合は候補から外し、離れた位置では従来どおり自由配置です。吸着中の柵同士は端点接続だけ許可し、中央で交差する配置は引き続き拒否します。
- **連続建築:** 建築物を1つ設置しても設置モードとゴーストを維持し、同じ種類を続けて配置できます。各設置はサーバーの応答を待ってから次を確定するため、連打による二重送信を防ぎます。設置を拒否された場合は、素材で払った分か所持済み建築物のどちらか、実際に使ったものだけを返却します。`Esc` または「キャンセル」で設置モードを終了します。
- **インタラクトと建築回収の分離:** PCでは `E` 短押しが採集・宝箱・洞窟・小屋などの通常操作、近くの自分の建築物の上で `E` を約0.48秒長押しすると回収メニューを開きます。メニューで「回収する」を選ぶまで回収は実行されず、`Esc` /「キャンセル」で閉じられます。スマホでは通常の `GET` ボタンと、建築物が近いときだけ表示される「回収」ボタンを分けています。回収した建築物は素材に分解せず、従来どおり手持ちに戻ります。
- **建築物の一括回収:** `B` でビルドメニューを開き、「建築物をまとめて回収」を選ぶと、10m以内の回収可能な建築物を一覧から複数選択できます。PCでは「ワールド上で選ぶ」方式も選択でき、選択中もWASDで移動できます。マウスカーソルを画面全体で動かして建築物をクリックし、右ドラッグで視点を変更できます。`Enter` で実行、`Tab` で一覧に切り替え、`Esc` でワールド選択を終了します。一覧の「表示中をすべて選択」「選択解除」も利用でき、選択した建築物はワールド上で琥珀色に光ります。サーバーは対象ごとに距離・所有権を再確認し、回収結果を返します。1回の要求で選択できるのは最大100件です。スマホでは従来のスクロール可能な一覧方式を利用できます。
- チャット: `Enter` で入力(日本語入力の確定Enterでは送られません)、もう一度 `Enter` で送信、`Esc` でキャンセル。スマホは左下の💬ボタン。発言は頭上の吹き出しと画面左下のログに出ます。エモートは `1`〜`4`(👋 🎵 ❗ ❤️)。1回60文字まで、連投は0.5秒間隔で制限され、`<` `>` は除去されます(`shared.js` の `CHAT_*`)。
- 設定: `O` キーか右上の「⚙ 設定」で、音量・マウス感度・画面の揺れのオン/オフを変えられます(ブラウザに保存されます)。
- **緊急脱出:** 設定から利用できます。移動入力を続けても8秒以上ほとんど位置が変わらない状態をサーバーが検知した場合にのみ実行でき、安全な陸地へ移動します。所持品や建築物は変化せず、使用後は3分間のクールダウンがあります。目的地は閉じた柵・門の内側、建築物、洞窟、海辺、敵やボスの近くを避けて検索します。設定を開いた瞬間に入力が止まる場合を考慮し、最後の移動不能入力から20秒間は検知状態を保持します。
- **水中からの水面表示:** 海面は裏面からも描画する設定にしてあり、水中から上を見上げたときも水面が表示されます。透明面が深度を書き込んで水中の透明表現を隠しにくいよう、深度書き込みも無効にしています。
- **海底オブジェクト:** 海底の採集ポイントはseed固定で80か所です。海藻24・サンゴ12・普通の貝殻16・真珠貝6・小石10・大岩12(石材)で、レア度が高いほど少なくなるようにしています。置いてあるものは全部拾えます(見た目だけの飾りはありません)。普通の貝殻と真珠貝は別アイテムで、サンゴと貝殻は図鑑「海のもの」に登録され、小石と大岩は既存の石材所持数に加算されます。1回の入手は1個で、再取得までは図鑑アイテム600秒・石材180秒です。数は `shared.js` の `getUnderwaterLayout`(`resourceTypes` と `extraPattern`)で変えられ、キーの上限は `MAX_UNDERWATER_RESOURCES`(u0〜u99)です。沈没船と海底宝箱を1か所追加し、宝箱は既存の古びた鍵と開封同期を再利用します。新しい宝箱は既存の陸上3個の後ろのindex 3に追加しているため、既存の陸上宝箱の場所・番号は変わりません。
- 敵に殴られると、攻撃された向きと反対へ弾かれ、画面の縁が赤くフラッシュします(向きはサーバーの `hurt` メッセージの `dx`,`dz`)。
- ミニマップはネタバレしにくくしてあります。洞窟は近づく(30m以内)と載り、以後は表示されます(ブラウザに保存)。未発見の遺跡は近く(45m以内)にいるときだけ薄く見えます。
- 続けて出る通知(トースト)は順番に表示され、溜まると短くなります。
- 体の当たり判定: プレイヤー・敵は互いに重なりません(半径は `shared.js` の `BODY_RADIUS`)。敵どうし・敵とプレイヤーの押し出しはサーバー、プレイヤー自身の押し出しは各クライアントが行います(プレイヤー同士はお互いに半分ずつ避けます)。1.2m以上高く跳んでいれば上を越えられます。
- 地形の障害物: 木の幹・岩・遺跡の石柱・洞窟の岩山には入れません(柵と同じく、プレイヤーの画面側で押し戻します)。低い岩は跳べば越えられ、洞窟は入口の手前まで近づけます。採集して消えた木や岩は通れるようになります。半径は木・岩を作る関数の `userData.bodyR` / `bodyH`、洞窟の岩山と遺跡は `staticSolids` です。敵(サーバー側)は木や岩をまだすり抜けます。小屋・焚き火・床にも判定はありません。
- PCの操作: マウスを固定している間は、画面左下に操作一覧(`B` ビルド / `C` 図鑑 / `O` 設定 / `Enter` チャット / `Esc` カーソルを出す)が出ます。右上のボタンはカーソルを出した状態で押せます(ボタンにもキーを表示)。`Esc` で解除した直後はブラウザが再固定を断るので、画面をクリックして操作に戻ります。
- 攻撃の向き: 攻撃してもキャラの向きはカメラに合わせて変わらず、今向いている方向(最後に動いた向き)に振ります。ダッシュ中は走っている方向へ踏み込みます。
- 接続が切れると自動で再接続し(最大2分)、最新のワールド状態で世界を作り直します。
- 敵は7種類です。数は `shared.js` の `ENEMY_WOLF_COUNT` など(狼10・猪8・岩トカゲ6・カニ8・クラゲ8・初期版の狼5・初期版の猪4)、HP・速さ・攻撃力・技・行動は `ENEMY_KINDS` で決まります(HPは狼6・猪8・岩トカゲ12・カニ6・クラゲ5)。倒すと60秒後に別の場所へ再出現します。
  - **狼(HP6):** 近づくと追って、周りを回ってから飛びかかります(8ダメージ)。 **猪(HP8):** 自分からは襲わず、殴ると突進で反撃します(12ダメージ)。
  - **初期版の狼・猪(`wolfClassic` / `boarClassic`):** 最初のバージョンの素朴な箱型の見た目を保ったまま、耳・尾・目・鼻・脚の関節と足先・背中の毛などを足したモデル(`makeWolfClassic` / `makeBoarClassic`。丸みや円錐は使わず箱だけで作っています)。強さと動きは狼・猪と同じで、見た目だけが違います。
  - **岩トカゲ(HP12):** 遺跡のまわりにいて、近づく(4.5m)までは岩のように伏せたまま動きません(目も見えません)。起きると追って噛みます(10ダメージ)。離れるとまた伏せ、殴られても逃げません。倒すと石材×2。動きは、伏せ/起床、歩き(対角の脚を振る・体と頭の揺れ・尾の揺れ)、起きる瞬間の伸びと身震い、噛みつき(体と頭を突き出して口を開閉)、息づかいです(`makeRockLizard` の `userData.anim`)。噛みつきは、サーバーが攻撃のたびに全員へ送る `eatk` 通知で再生します。
  - **カニ(HP6):** 浜(高さ0.35〜1.2)にいて、普段は横歩き、近づくとはさみを前へ向けて挟みます(6ダメージ)。正面からの攻撃は防ぎます。
  - **クラゲ(HP5):** 海中(海底の高さ-9.5〜-1.0)をゆっくり漂い、水の上にいるプレイヤーへ近づいて周囲にパルスを出します(8ダメージ)。体は水面より下に収まります(`jellyHeight`)。
  - **水辺の扱い:** 敵は生息域(陸・浜・水中)の外へは入れません(`enemyCanStand`)。外へ出る移動は取りやめて手前で止まり、ワープはしません。陸の敵はひざ下くらいの浅い水までは追ってきます。深い水の中など、敵が届かない場所のプレイヤーは狙いません(`enemyCanReach`)。届かない場所から殴られた敵は、一方的に殴られ続けないよう距離を取ります。追っている最中に止められ続けたら、あきらめて初期位置へ歩いて戻り(戻る間は襲ってこない)ます。
  - 新しい敵を足すには、`ENEMY_KINDS` と `ENEMY_ORDER`、生息域(`pickEnemySpot`)、`index.html` のモデルと `ENEMY_MAKERS` を足します。モデルの動きは `userData.anim`、横歩きは `userData.rotOffset`、水中に浮くのは `userData.floats` で決まります。
  - **技(予備動作→本攻撃→のけぞり):** 敵は近づいたら即噛むのではなく、予備動作(`windup`)を見せてから本攻撃(`dur`)を出し、そのあと隙(`recover`)ができます。技の数字は `ENEMY_KINDS` の `moves` にあります(`trigger`=出す距離、`hitR`=当たる範囲、`dash`=突っ込む)。予備動作の間に殴ると技が中断されてのけぞります。
    - 狼: 相手の周りを回り(`orbit`)、近づくとしゃがんで飛びかかる(`lunge`)。向きは本攻撃の直前に固定されるので横へ避けられる。HPが1/3以下になるまでは逃げない。
    - 岩トカゲ: 噛みつき×2のあと、3回目は尻尾の薙ぎ払い(`whip`、範囲が広く予備動作が長い)。
    - カニ: 正面からの攻撃はハサミで防ぐ(`guard`=ダメージを1減らす)。側面・背後、挟んだあとののけぞり中は通る。向きを変えるのが遅い(`turn`)。
    - クラゲ: 近づいて(`hold`)触手を広げ、周囲へパルス(`pulse`)。範囲の外へ離れればかわせる。
    - 猪: 殴られると逃げずに、予備動作のあと突進(`charge`)で反撃する。
    - クライアントは予備動作の間、当たる範囲を地面に赤く表示します(円=周囲への攻撃、帯=突進・飛びかかりの通り道)。確認用に `__dbg.models.movePose('狼,lunge,1,0.45')`(種類,技名,段階1〜3,経過秒)で姿勢を出せます(`window.__LOWPOLY_DEBUG=true` のとき)。
  - スナップショットの敵データは `[id, x, z, ry, 起きているか, 状態コード]` です。状態コードは `(段階+1)*10 + 技番号`(段階: 0=予備動作 1=本攻撃 2=のけぞり、技番号は `MOVE_ID`)、0は技なしです。本攻撃の瞬間には `{t:'eatk', id, mv}` も配信されます。殴られたときの `ehit` には、ガードされたとき `g:1` が付きます。
- 敵に殴られるダメージはサーバーが判定して本人に通知します。洞窟内のプレイヤーは襲われません。
- **灯台:** 島の外周に近い、平らな岬に1つ立っています(紅白の塔、外側のらせん坂、頂上の展望台とレンズ室、回る灯りの光の筋)。場所はseedから決まり(`Shared.getLighthouseLocation`)、サーバーとクライアントで同じ値になります。坂は反時計回りに3周して高さ21mの頂上へ登れます(坂・床の高さは `Shared.lighthouseFloorY`、寸法は `Shared.LIGHTHOUSE`)。1歩で登れる段差は0.9mまでで、坂の下を通る人は頭上の坂に吸い上げられません。塔の本体は固体で、カメラは塔の中へ入らないよう外へ押し出されます。坂と頂上の外側の手すりにも当たり判定があり(`Shared.lighthouseRailClamp`)、坂・展望台の上にいる人は縁から外へ出られず、跳んでも越えられません(面から2.5mまで)。坂の下の地面を歩く人と、地面に近い登り口(1m以内)は対象外で、外から歩いて乗れます。地面を歩く敵(狼・猪・岩トカゲ・カニ)は、足元の地面から3.5mより高い所にいるプレイヤー(坂の上・頂上)には届かず、狙わず、技も当たりません(`Shared.enemyCanReach` の高さ判定。ジャンプや建てた床の上は従来どおり届きます)。灯台・泉・野営地のまわりには木・岩・草を置かない円があり(`Shared.getFeatureClearZones`)、坂や池に重なりません(ほかの木・岩の位置は変わりません)。頂上に着くと初回だけ通知が出ます。
- **湧き水の泉:** 島に2か所、小さな池があります(ふちの石・水辺の草・昇るきらめき・広がる波紋)。入っている間、HPが毎秒4ずつ回復します(焚き火は毎秒6)。池の水平距離3.2m以内で、高さの差が2.5m未満のときだけ有効です。場所はseedから決まり(`Shared.getSpringLocations` / 寸法と回復量は `Shared.SPRING`)、初期位置・遺跡・ボスの持ち場・灯台・洞窟を避け、泉どうしは60m以上離れます。回復はHPと同じくクライアント側で処理し、サーバーの状態やセーブ形式は変えていません。
- **敵の野営地:** 島に3か所、人型の番人が各4体ずついる陣地があります(焚き火、テント、旗、杭など)。場所はseedから決まり、初期位置・遺跡・ボス・灯台・泉・洞窟を避け、野営地どうしも離して配置します。番人は各自の野営地周辺を巡回し、プレイヤーを見つけると追跡して棍棒で攻撃します。倒しても60秒で再出現します。各野営地の戦利品箱は、その拠点の番人を全員倒したときだけ開けられます(サーバー側で判定)。最初の野営地と海底洞窟の宝箱番号(5・6)は維持し、追加2か所の箱は末尾に追加します。宝箱は最大9個です。JSONバックアップも最大9個まで扱います。
- **海底洞窟:** 沈没船のまわりの海底(深さ6〜9m)に、岩でできた丸い小部屋が1つあります(入口は1か所、天井の岩の板、奥に光る水晶とサンゴ)。場所はseedから決まり(`Shared.getGrottoLocation`)、天井の上面まで水中に収まる平らな海底で、沈没船・海底の採集物と重なりません。壁の当たり判定は輪状の円(`Shared.grottoWallSolids`)で、入口以外は通れず、壁の上(天井の高さより上)は泳いで越えられます。中から上へ泳いでも天井は抜けられず、外から上を泳いでも天井の板には入れません。中にいる間、カメラは壁の内側・天井の下へ押し戻されます。中をクラゲ3匹が漂い(敵のidは野営地の見張りの後ろ、`Shared.isGrottoEnemyId`)、洞窟から出ないよう持ち場の近くだけを漂い、倒しても60秒で再出現します。奥の宝箱(宝箱の6番)は鍵が要らず、潜って近づけば開けられます(水面の上からは開けられません)。報酬は深層クリスタル1個と古代の欠片×2です。宝箱は最大9個になり、従来のindex 0〜6を維持し、追加野営地2か所の宝箱を末尾へ追加します。6個までの古いセーブもそのまま読み込めます。JSONバックアップの宝箱上限は9個です。
  - **頂上の宝箱:** 宝箱は5個になりました(陸3・沈没船1・灯台1。番号は追加順で、既存の番号は変えていません)。灯台の宝箱は頂上まで登らないと開けられません(クライアントは高さの差が3m以内のときだけ操作でき、サーバーも高さを4mまでで検証します)。他の宝箱と同じく古びた鍵が必要です。以前の4個までのセーブは、そのまま読め、灯台の宝箱は未開封で始まります。
  - 敵は塔をすり抜けます(他の木・岩と同じ既知の制限)。


### ボス「遺跡の石の守護者」
- 島に1体だけ。持ち場は「スタート地点から一番遠い遺跡」(`getBossHome(seed)`。seedから決まるので全員同じ場所)。体力60、倒すと3分後に持ち場で復活します。
- 動き・体力・攻撃のタイミングはすべてサーバー(`shared.js` の `updateBoss`)。クライアントは見た目・予告表示・HPバーだけです。
- 眠っていて、17m以内に近づく(または攻撃される)と起きて追ってきます。見失って5秒たつと持ち場へ戻り、体力が全回復します。洞窟内・死亡中のプレイヤーは狙いません。
- 攻撃は2種類。近いときは **叩きつけ**(自分の周りの赤い円、ダメージ24)、離れているときは **落石**(プレイヤーの足元に赤い円と頭上の岩、ダメージ16)。先に予告(`batk`)が届き、溜め終わりの瞬間(`bimpact`)にその時の位置で判定するので、赤い範囲から出れば避けられます。体力が半分以下になると範囲が広がり、溜めが短くなり、落石が増えます。
- 倒すと、近く(45m以内)にいる生存者全員が「古代の欠片 ×5」と古代金貨を受け取ります。
- 調整する値は `shared.js` の `BOSS_*` と `BOSS_ATTACKS`。見た目は `index.html` の `makeGuardian`(標準)と `makeGuardianBrute`(いかり肩)。使う方は `GUARDIAN_MODEL` (`'stone'` か `'brute'`)で切り替えます。
- 通信: 攻撃は `hitboss`、サーバーからは `bhit` / `bdead` / `bspawn` / `batk` / `bimpact`、スナップショットの `b`(`[x,z,ry,状態,体力]`)。
- ボスの状態は保存されません(サーバー再起動で全回復して持ち場に戻ります)。

### 監査後の追加修正(v5)

- 宝箱を置く遺跡を、先頭3か所に固定せず、全遺跡からseed付きシャッフルで3か所選ぶように戻しました。これはv4で入った意図しない配置偏りの修正です。宝箱座標が変わるため `WORLD_LAYOUT_VERSION` を3へ上げました。v4の `world.json` から建築物は維持しますが、開封済み宝箱の状態は引き継がれません。更新前に `world.json` をバックアップしてください。
- 洞窟の移動可能半径をクライアントの `CAVE_ROOM_R` と一致させました。壁際でサーバーだけが位置更新を拒否する不整合を防ぎます。
- 位置更新にクライアントの単調増加時刻を付け、WebSocketの受信がまとめて届いた場合も送信時刻の差で移動量を検証します。短時間のワープは引き続き拒否し、通信遅延後に正当な位置へ戻れなくなる問題を避けます。旧クライアントから時刻が届かない場合は受信時刻を使います。
- 採集キーの数字部分を現在の生成数上限内に制限し、先頭ゼロなど実際には生成されない形式や、鉱石/アイテム種別の食い違いを拒否します。現在の資源配置の理論上限438件に対してMap上限を512件とし、キー上限の到達で通常採集が止まらない余裕を確保します。
- ただし採集物の個々の座標をサーバーで再生成していないため、上限内の実在し得るキーを遠隔で先に取得扱いにする不正までは防げません。座標照合を追加するには、描画モデルの乱数に依存した配置を独立した共通データへ整理する必要があります。今回はその再設計を混ぜていません。

## 海底の見た目を変えたいとき

- 海の中の見え方: 海面より下の地面は、深いほど青緑がかった暗い砂色になります(`index.html` の地形の色分け、`cSeabed` / `cSeabedDeep`)。カメラが海面より下に入ると、霧が青緑で濃くなり遠くが霞みます(`updateWaterFog`、`WATER_FOG_*`)。
- 宝箱: ふたは断面が半円のかまぼこ形で、蝶番は奥側。開くと本体の上で後ろへ倒れ、中の内張りと金貨が見えます(`makeChest`。開く角度は `CHEST_OPEN_ANGLE`)。海底の宝箱には藻とサンゴが付きます(`decorateSunkenChest`)。

海底の海藻・サンゴ・貝殻(真珠貝)・小石・岩・沈没船は `public/index.html` の「海底の景観と採集物」の節(`makeUnderwaterSeaweed` / `makeUnderwaterCoral`(変種0=枝・1=テーブル・2=筒) / `makeUnderwaterShell`(真珠貝=開いた二枚貝、普通の貝殻は変種で二枚貝/巻貝) / `makeUnderwaterPebble` / `makeUnderwaterRock` / `makeSunkenShipwreck`)で作っています。陸の岩・草と同じく、面ごとの平らな塗りと位置から決まる頂点のゆらぎ(`roughen`)でそろえています。形の乱数は変種番号から決まるので、見るたびに形が変わることはありません。配置・採集の仕組み(`shared.js` の `getUnderwaterLayout`)は触らずに、見た目だけ差し替えられます。

## モデル(見た目)を変えたいとき

木・岩・草・結晶・枯れ木・敵・建築物のモデルは、`public/index.html` の `makeXxx` 関数(`makeConiferTree` / `makeCraggyRock` / `makeHerb` / `makeWolf` など)で作っています。
岩・結晶などの凹凸は `roughen()`(位置から決まるずれ)を使うので、面の間に隙間ができません。宝箱と遺跡の座標は描画モデル用の乱数から独立しています。配置ルールそのものを変えた場合は `WORLD_LAYOUT_VERSION` を更新してください(旧セーブの宝箱開封状態は自動的にリセットされます)。
建築物(`makeCampfire` / `makeHut`(丸太小屋)/ `makeCabin`(板張りの家)/ `makeFence` / `makeGate` / `makeFloor`)を作り変えるときは、`userData.footprint`(置ける間隔)・柵の長さ2.0と杭の位置±0.9(当たり判定が `resolveFenceCollision` の `halfLen`)・床の半径 `FLOOR_RADIUS`・焚き火の `flameParts`/`embers`(揺らぎ)・扉が +z 側、の約束を保ってください。

## 洞窟の外観を変えたいとき

位置は `public/shared.js`、見た目は `public/index.html` の「洞窟の外観」セクションにまとまっています。

- 位置と向き: `shared.js` の `CAVE_SITES`(洞窟を足す・動かすのはここだけ。サーバーの判定にも使われます)
- 見た目: `buildCaveExterior()`(岩山 / 開口部とトンネル / 松明と光る鉱石 / 飛び石、の4ブロックに分かれています)
- 入口判定の基準: `CAVE_MOUTH_OFFSET` と `DOOR`(見た目を変えても、開口部の手前 `DOOR.z0` と合わせておけば他のコードは触らずに済みます)
- 洞窟エリアには木・岩・草を置かない(`isInsideCaveArea`)

洞窟の外観や位置を変えた場合は、洞窟周辺の配置と `isInsideCaveArea` の整合性を確認してください。遺跡・宝箱の座標は洞窟モデルの乱数消費には依存しません。


## 地上洞窟の内部 (v45)

地上洞窟は今の画面切り替え方式を維持し、中央祭壇・低い石柱・奥壁の古代文字風の刻印・出口から続く石畳を加えて遺跡ダンジョンらしい見た目にしています。これらは装飾メッシュのみで、移動範囲・衝突判定・アイテム・敵AIは変更していません。海底洞窟のようなシームレスな入室にする改修は別作業として切り分けています。

## 洞窟の内部を変えたいとき

`public/index.html` の「洞窟の内部」セクション(`buildCaveInterior`)にまとまっています。

- 広さ: `CAVE_ROOM_R`(歩ける半径。画面側で押し戻します)と、岩の外殻の `CAVE_SHELL_R / CAVE_SHELL_CY / CAVE_SHELL_RY`
- 明かり: 環境光+固定の点光源3つ(ゆらぎは `caveAnims`)。点光源は増減すると描画の再コンパイルが走るので、飾りの光はキノコのように発光素材で出します
- 飾り: 大岩の輪・小石・つらら石・石筍・光るキノコ・壁の大結晶・出口(奥の壁の岩のアーチと外の光。松明の `makeTorch` は外観で使用)
- 出口は `exitLocal`(Eで外へ出る位置)と `ARCH_Z`(アーチの位置)で決まります
- 乱数の呼び出し回数を変えると島の生成も変わるので、変更後は `world.json` を消してください

## 既知の制限

- 位置同期は移動量と経過時間を照合し、洞窟の出入りも入口・出口付近からの遷移に限定します。同じ敵への攻撃は260msの間隔を設け、死亡中・洞窟内の建築回収も拒否します。
- ただし初回の位置同期は再接続との互換性のため受け入れています。宝箱と今回追加した海底資源の座標はサーバー側で再生成して距離判定しますが、既存の陸上/洞窟採集物すべてがサーバー側の正規レジストリに移っているわけではありません。改造クライアントへの完全なチート対策ではなく、所持品・図鑑・剣強化もクライアント側保存です。
- 緊急脱出はサーバーが受け取った移動状態を使って判定しますが、クライアントの全ての障害物をサーバーが再現しているわけではありません。通常の移動が可能なのに移動不能と判定される／されない場合があり、実際のマルチプレイでの検証が必要です。
- 昼夜サイクルやクラフトの用途追加などのゲームデザイン面は未着手です。ボスは実装済みですが、ボス報酬をクラフトや装備強化につなぐ仕組みは今後の改善候補です。

`public/shared.js` の `BUILD_IDS` と `BUILD_RADIUS`(サーバーの検証と共有)、`index.html` の `BUILDABLES` と `heldStructures` に同じ id を足します。小屋で眠る処理は `hut` と `cabin` の両方が対象です。


## セーブデータの書き出し・読み込み

- 設定画面(`O` または右上の「設定」)の「セーブデータ」から、JSONバックアップをダウンロード/読み込みできます。
- バックアップには、ブラウザごとの所持品・収集アイテム・図鑑・剣強化・所持建築物・設定と、共有ワールドのシード・建築物・宝箱の開封状態が入ります。ブラウザの秘密キーやプレイヤー名は含めません。
- 読み込みは現在のプレイヤー進行状況を置き換えるため、実行前に確認が出ます。ファイルは最大256KiB、未知の形式・不正な数値・不正な建築IDなどは拒否します。
- **オンラインで共有ワールドを復元すると、同じサーバーの参加者全員に影響します。** サーバー起動時にコンソールへ表示される「共有ワールド復元キー」を設定画面の入力欄に入れ、読み込み時にワールド復元を選んでください。キーを環境変数`SAVE_ADMIN_TOKEN`で指定した場合は、その値が管理者キーです。キーはJSONバックアップには保存されません。
- ワールドの復元では、島のシード・建築物・宝箱状態をバックアップの内容へ置き換えます。シードが変わる場合、参加者全員のブラウザが再読み込みされます。採集物の一時的な再出現タイマー、ボスの戦闘状態、プレイヤーの所持品はワールド側には含まれません。
- 管理者キーが空欄の場合、オンラインではプレイヤーデータと設定だけを復元し、共有ワールドは変更しません。ソロプレイでは管理者キーなしで共有ワールドを復元できます。
- ソロプレイの共有ワールドはブラウザの`localStorage`へ30秒ごと・タブ終了時に保存されます。オンラインの共有ワールドはサーバーの`world.json`へ自動保存されます。大事なバックアップは、インポート前に別名で保管してください。

## 柵の当たり判定修正

柵の衝突判定を、表示モデルと同じThree.jsのY回転に合わせた共通関数(`Shared.resolveFencePoint` / `Shared.moveFencePoint`)へ統一しました。以前は回転変換の符号がモデルと逆で、斜め・90度に回した柵の当たり判定が見た目とずれていました。通常移動・被弾ノックバック・攻撃の踏み込み、サーバー上の敵/ボスの柵判定でも共通の計算を使用します。高速移動の一部で柵を飛び越えないよう、横移動を小さい区間に分けて衝突を解決します。


## 門（Gate）

- 建築メニューから木材5個で門を設置できます。柵と同じ幅・端点ルールで接続でき、端点への自動吸着にも対応します。
- 木材5個で建築でき、柵と同じ幅で端点接続・自動吸着できます。近くでEキー（スマホはGET）を押すと開閉します。E長押しで既存の建築物回収メニューも利用できます。閉じた門だけが柵と同じ衝突判定を持ち、開いた門は通行できます。開閉状態はサーバーで同期され、ワールドのセーブ・インポートにも含まれます。
- 門の開閉状態はサーバーで管理し、全参加者へ同期し、ワールド保存／インポートにも含めます。開いている門はプレイヤー・敵の柵衝突判定から除外します。
